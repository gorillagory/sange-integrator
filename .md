We are working on a Laravel + Inertia/Vue multi-tenant SaaS called sange-integrator.

Important rules:
1. Full code only, no partial snippets.
2. Minimal explanation.
3. No god components. Break into small maintainable files.
4. Prefer backend/frontend pieces in clean modules.

Current architecture:
- control DB = landlord/global DB.
- tenant/shared = tables every tenant database gets.
- tenant/{industry} = industry-specific tables.
- companies are tenant-local operational environments.
- main_group_companies are umbrella/head groups.
- companies belong to main_group_companies.
- users, roles, permissions, companies, main group companies, global clients, schemas live in control.
- contracts are tenant/shared because every company has its own contracts.
- bookings/passengers/booking_services are tenant/travel.

RBAC:
- Spatie permission teams enabled.
- team_foreign_key = company_id.
- global/system team id = 0.
- ResetPermissionTeam sets PermissionRegistrar team id to 0.
- IdentifyTenant sets PermissionRegistrar team id to current company id.
- super_admin does not need company membership.
- non-super operational users should be assigned to companies.

Current issue:
Creating company failed because submitted company.db_name was “bayam-travel”, but TenantProvisioningService only allowed letters/numbers/underscore and threw:
“Tenant database name is invalid.”

We decided to normalize database names:
- allow user input with dash
- normalize dash/dot/space to underscore before creating database
- store normalized db_name in companies table
- blank db_name should auto-generate from subdomain as tenant_{subdomain}
